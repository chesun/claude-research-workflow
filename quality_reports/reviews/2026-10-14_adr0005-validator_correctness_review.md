## Verdict

The production change does what ADR-0005 items 1–3 and 5 and the Task 1 Interfaces block say, in the specified order, and I found no correctness bug in it. `SIGNED_OFF_RE` and `OVERRIDE_RE` are byte-identical to the plan; `CARD_AUDIT_RE` adds a harmless `^` anchor; `MARKS` matches; `_card_problem(f, n, card, bp, root)` runs the existing header checks then checks 1–7 in the plan's order (bin/blueprint_check.py:399–454); the old-format re-sign message matches Review Focus 1 verbatim and includes the exact 12-hex prefix to copy. All three suites pass (`py -I bin/test_blueprint_check.py` 166/0, `test_lean_check.py` 199/0, `test_blueprint_tools.py` 74/0); `lean_check.py`'s card check (bin/lean_check.py:680–697) reads only Node / Node statement hash / Lean / Statement SHA-256 / Audited statements, none of which this change touches, and `blueprint_tools.py` reads no cards. The `_check_node` formalized/verified branch and the `verified` newest-report check are unchanged apart from the extended `_card_problem` call, and the replay property holds: on a copy of the real BDD blueprint the pilot card fails both its `formalized` and `verified` lines with `the card is signed in the pre-ADR-0005 form ('CS 2026-10-13'); re-sign as `<initials> <date> sha:a6cb62a1734a`...` — exactly the Task 4 Step 1 expectation. Verdict vocabulary stays PASS/UNVERIFIED/FAIL, and every new error reaches the user prefixed with the node label and names the fix. The deductions are all on the test side: mutation testing (9 + 3 mutants, run in a scratch copy) shows the two checklist-mark tests pass for the wrong reason, and four production rules have no killing test at all. The rules themselves are correct today; the gaps mean a future regression in them would ship silently.
