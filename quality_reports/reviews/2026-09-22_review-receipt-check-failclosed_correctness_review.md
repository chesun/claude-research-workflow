## Verdict

The scoped fail-closed redesign is fundamentally sound: exit 2 is reachable **only** from the confirmed-gated-commit path (after the not-a-commit, waiver, and `review.required` gates), the outer `__main__` backstop and every pre-gate error path fail open with exit 0, and the `git_checked`/`git_soft` split is correct — the gated calls (`diff --cached`, `ls-files`, `cat-file`) all exit 0 on the empty-repo / first-commit / detached-HEAD cases I built, so no benign-nonzero sibling of the fixed `git log` empty-repo case is wrongly caught. The suite passes 39/39 and the exit-code matrix behaves exactly as specified in every throwaway repo I constructed. **However**, there is one real, shipping bug: `Path` is used in `_log_failure` but never imported, so the durable audit log (`.claude/state/review-gate-failures.log`) is **never written** — the `NameError` is silently swallowed, defeating the module's stated "auditable even if the banner scrolls away" guarantee and making `_fail_closed`'s "see .claude/state/review-gate-failures.log" instruction point at a file that will never exist. The test suite masks this because it monkeypatches `_log_failure` away in-process and never exercises a real-repo fail-closed, so the bug stays green. The block/allow decision itself is unaffected; the defect is confined to observability.

## What is correct (with evidence)

- **Fail-closed scoping (Check 3): SOUND.** Exit 2 originates only from (a) `code_missing → return 2` (line 364) and (b) `_fail_closed → 2` inside the gated `try` (lines 344-347), both after the not-commit / waiver / `review.required` gates (lines 312-322). The `__main__` backstop catches any exception from `main()` and exits 0 (lines 373-381). Verified: non-Bash tool → 0 (TEST F); malformed stdin → 0 (suite); `parse_commit` runs outside the try, so a parse crash hits the backstop → 0.
- **git_checked vs git_soft split (Check 1): SOUND.** On an **empty repo, first commit**: code+receipt → exit 0 (TEST B), code+no-receipt → exit 2 (TEST C) — i.e. `diff --cached`, `ls-files`, `cat-file` all succeed with no HEAD, and `last_commit_date` correctly returns `None` (freshness vacuously satisfied) so a legitimate first commit is not blocked. **Detached HEAD**: unreviewed code → exit 2 (TEST E), not a spurious fail-closed. No benign-nonzero sibling of the fixed `git log` case was found among the gated calls.
- **Exit-code matrix (Check 2): SOUND.** Non-Bash → 0; non-commit → 0; waived → 0 even when the git path would fail (in-process `boom` + waiver → 0); `review.required` unset → 0 (and no fail-closed); code missing receipt → 2; code with valid staged receipt → 0; doc-only missing → 0 (advisory printed); git error in gated path → 2; malformed stdin → 0. All confirmed via suite + my throwaway repos.
- **Regressions hold (Check 4): SOUND.** Nested `.claude/hooks/tests/`, `lib/`, `bin/sub/` classify as `code`; `quality_reports/plans/INDEX.md`, `README.md`, `paper/main.tex` → `None`; waiver honoured only as a leading env token (message-body `REVIEW_WAIVE=1` → still blocked); receipt missing `**Score**` rejected; stale receipt (dated before last commit) blocked. All green in the suite; freshness works with the now-tolerant `last_commit_date`.
- **`_log_failure` non-throwing contract (Check 5): partially SOUND.** It never propagates an exception (bare `except`), and the not-in-a-repo fallback (`root = "." `) is reasonable — but see the High finding: it also never *succeeds*, so the "durable, greppable record" does not exist.
- **Test suite (Check 6): 39/39 passed.** Uncovered/would-stay-green-if-broken: the `_log_failure` real write (High bug), real-repo fail-closed banner + exit-2-on-git-error, empty-repo/first-commit, detached HEAD, `target_matches` basename-uniqueness and ADR-number matching (no direct test), and the outer-backstop exit-0-on-pre-gate-exception path.
