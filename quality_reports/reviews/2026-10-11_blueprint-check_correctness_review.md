# Blueprint validator Review — correctness
**Date:** 2026-10-11
**Reviewer:** correctness critic (independent, general-purpose agent)
**Target:** bin/blueprint_check.py, bin/test_blueprint_check.py
**Score:** 78/100
**Status:** Active

## Verdict

The validator implements every rule in the plan's Task 1–3 tables (G1–G4, S1–S3, E1–E5, L1, V) and all five Review Focus items hold on this machine: CRLF and BOM files parse and hash identically, a filename/label mismatch is an error, backslash and `:N-M` locators resolve, absolute and `..`-escaping locators give UNVERIFIED, and a statement edited after logging is a FAIL. The shipped suite passes 50/50 on Python 3.14.8. Three defects keep it below the commit gate: (1) on Windows with the default console code page any non-ASCII character in a printed error, warning or path raises `UnicodeEncodeError` after the verdict line, so the process exits 1 regardless of verdict — a PASS or UNVERIFIED blueprint reports as FAIL; (2) with no enclosing `.git` (the plan's Task 11 scratch-copy scenario) every `survived-search`, `checked` and `refuted` node FAILs with a misleading "needs an existing check file" message rather than UNVERIFIED, and the CLI offers no `--repo-root` escape; (3) an empty `## Statement` passes. The tests are mostly meaningful, but a mutation pass shows two plan-named negative tests are masked by neighbouring rules and a sizeable set of implemented rules has no test at all (24 of 36 single-point mutants survived). All findings are small to fix; none requires a redesign.
