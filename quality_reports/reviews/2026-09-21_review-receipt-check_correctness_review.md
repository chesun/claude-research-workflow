## Verdict

The hook is soundly engineered on almost every axis the spec calls out: it fails open on every internal-error path (malformed stdin, non-repo cwd, git failure, config unset), gates only on `git commit` after correctly skipping env prefixes / `cd &&` / `-c` global flags, parses the staged index with `core.quotePath=false -z -M` including renames (old path flows into freshness) and deletions, validates receipt Score/Status/Date fields, and matches targets with precise boundary guards (exact path, `./` prefix, backslashes, unique-vs-non-unique basename, `ADR-NNNN`/`#NNNN`, prefix/substring collisions). I ran the shipped suite (29/29 pass) and 33 additional adversarial checks in throwaway repos; 32 of the 33 behaved as the spec requires. The one real behavioral defect is a **false-waive**: the `REVIEW_WAIVE` token is matched anywhere in the raw command string, so a commit *message* (or any other segment) that merely contains `REVIEW_WAIVE=1` silently waives the code block — a bypass of the hook's one blocking function, and one that triggers precisely when committing changes about the review system itself. A secondary latent gap: classification narrows the rule's `.claude/hooks/**` to *non-nested* script-extension files, so future nested hook code (`.claude/hooks/lib/*.py`, `.claude/hooks/tests/test_*.py`) escapes the gate. Everything else is correct.

## What is correct (with evidence)

- **Fail-open on every error path (exit 0), block-2 only for the deliberate result.** Malformed stdin → 0 (shipped test); non-repo cwd → 0; git-config/git-diff failure via `git_soft`/`git_soft_bytes` returning empty → 0; top-level `except Exception` at lines 283–286 → 0. Verified in control-flow probe (`non-repo dir exit: 0`). Exit 2 occurs only for staged code + no receipt + not waived (lines 260–271).
- **Opt-in gating.** `review.required` unset/false → exit 0 even with unreviewed staged code (line 232; shipped `optout` test + control-flow probe `review.required unset exit: 0`).
- **Trigger discrimination.** Non-Bash tool → 0 (line 226; probe `non-Bash tool exit: 0`); non-commit command → 0 (shipped tests `git status`, `git log --grep commit`, `echo commit && ls`); nothing gated → 0 (probe `nothing-gated (only README) exit: 0`).
- **`git commit` detection** handles `cd "dir" &&`, env prefixes, `-c key=val` global flags (2-token skip), `--amend`, and heredoc first-segment (shipped `parse_commit` cases, all pass).
- **Staged-change parsing.** Rename: old path flows into freshness — a rename whose old path was committed today + a 2020 receipt is correctly blocked (probe 2), and a fresh receipt on the new path is allowed (probe 2b). Deletion of a code file is gated (probe 3). Uses `core.quotePath=false` + `-z` for non-ASCII/quoted paths (lines 114–116).
- **Receipt validation.** Missing Score → rejected/blocked (probe 10); `Status: Superseded` → rejected (probe 9); `Status: Completed` → accepted (probe 9b); `Score: PASS` (non-numeric) → rejected (`_SCORE` requires `NN/100`); score `100/100` and `5/100` accepted (probe 14).
- **Receipt sourcing = staged index only.** `indexed_reviews` reads `ls-files --cached` + `cat-file -p :path`; a receipt on disk but not `git add`-ed is ignored → blocked (probe 8).
- **Target matching precision.** Exact path, `./` prefix, and backslash targets all match (probe 5/5b); unique basename matches (6b) but a non-unique basename does **not** (6); generic basenames (`README.md`/`SKILL.md`/`index.md`/`__init__.py`) excluded from basename matching (19); `ADR-0002` and `#0002` match `decisions/0002_*` while `ADR-0003` does not (4/4b/4c); prefix/substring collisions rejected (`new.py` not matched inside `new.pyc`; `bin/a.py` not matched by `bin/xa.py`) (17/20).
- **Freshness core.** Stale receipt (older than last commit) blocked (shipped `stale` test); equal-date accepted (probe 12); future-dated rejected (probe 7); brand-new file with no prior commit accepts any non-future date (`since=None` path, lines 199/215).

## Method

Ran the shipped suite (`python .claude/hooks/test_review_receipt_check.py` → `29/29 passed`), then 33 adversarial checks: 28 via a throwaway-git-repo harness (probe2.py) exercising e2e exit codes, plus 5 control-flow checks and direct `target_matches`/`classify`/`_SCORE` unit calls. 32/33 matched the spec; the one failure is the High finding above. All throwaway repos were removed. No repository source file was edited.
