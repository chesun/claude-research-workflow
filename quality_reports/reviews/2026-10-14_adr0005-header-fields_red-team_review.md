# ADR-0005 header_fields fix Review — red-team + correctness
**Date:** 2026-10-14
**Reviewer:** red-team + correctness critic (independent, general-purpose agent)
**Target:** bin/blueprint_check.py, bin/test_blueprint_check.py
**Score:** 88/100
**Status:** Active

## Verdict

The change is correct and fails in the safe direction. `header_fields` (bin/blueprint_check.py:441-455) now parses the first 60 lines of `_visible(text)`, and `_visible` (bin/blueprint_check.py:356-359) blanks comments and fences while preserving line count, so the 60-line window covers the same physical lines as before; a probe confirmed a field at line 60 is read and one at line 61 is not, before and after blanking. Unclosed `<!--`, unclosed fences, and mismatched fence markers match nothing and hide nothing, so a malformed card cannot silently lose its header — the worst malformed-input outcome observed is fields disappearing, which every caller turns into a loud failure (`_card_header_problem`, `_lean_report_problem`, the audit-report checks at bin/blueprint_check.py:513-531), never a silent pass. CRLF and BOM are handled (probe: fields read from a BOM+CRLF file with an inline comment). `duplicated_fields` (bin/blueprint_check.py:362-370) uses the same `_visible` and the same `utf-8-sig`/`errors="replace"` read (bin/blueprint_check.py:475, 508 vs 448), so the two now agree on what counts: a commented duplicate is neither read nor flagged as a duplicate. Real files are unaffected: `lean_check.render_report` (bin/lean_check.py:797-804) writes bare `**Key:** value` lines with no comments or column-0 fences in the first 60 lines; the card template and the card-auditor header spec (.claude/agents/card-auditor.md:63-71) put all fields above any comment. All three suites pass: `py -I bin/test_blueprint_check.py` 184/184, `py -I bin/test_lean_check.py` 204/204, `py -I bin/test_blueprint_tools.py` 74/74. Two real gaps remain: the sibling reader `lean_check.card_fields` was not given the same fix, so the two checkers of the same card header now disagree on commented-out fields; and the `Mode`-filter in `newest_lean_report` means a commented-out header now makes the validator skip a newer failing report in favour of an older PASS (confirmed by repro), though an editor of that file could always have forged the verdict directly. One of the two new tests (`rv_override_in_inline_comment_ignored`) also passes on the pre-change code, so only the comment-block test actually pins the fix.
