## Verdict

Revision 3 resolves every Critical and High and all but one Medium from the two redesign reviews, each with a code change and a pinning regression test: the quote-aware heredoc scanner (`_unquoted_heredoc_starts`, guard:430–456) closes the quoted-`<<` swallow (RT-C1, Corr-1); the whole-line shell scan (guard:490–491) closes `cat <<EOF | bash` (RT-C2); the per-segment loop with per-segment bypass, cd tracking and all three tiers (`check_command` guard:660–689, `_check_segment` guard:599–605) closes the bypass-disarms-the-chain findings (RT-H1, Corr-3) and the Tier-2 chain gap (RT-M2); `_WRAPPER_OPT_ARG`/`--` handling (guard:420, 518–526) closes `env -u X` / `env --` (RT-H2); the skip-any-dash git-option scan (guard:532–536) closes glued `-ckey=val` and unknown global options (RT-M1); `_parsed_segments` punctuation splitting closes the glued `cd X;` miss (RT-M3); `_normalize`'s marker stripping closes `( … )` / `{ … ; }` (RT-M4); `_is_force_push`'s `args[1:]` `+`-scan closes `git push origin +main` (RT-M5); `_BYPASSED_SHELL_RE` (guard:427, 492, 648–650) closes the un-bypassable heredoc block (Corr-4); the inner-debug merge (guard:652–657) closes the heredoc bypass-audit loss (Corr-2, with the log test at test:805–811). The suite passes **126/126** (`py -I .claude/hooks/test_destructive_action_guard.py`), matching the rule doc's count, and `post-rewrite-verify.py`'s imports (`_strip_env_assignments`, `_consume_cd_chain`, predicates) are all intact. The full audit-log replay — **1,560 unique (command, cwd) pairs** from `.log` + `.log.old`, HEAD vs revision 3, real (un-patched) shared prefixes — produced **0 errors, 0 new blocks, exactly 6 BLOCK→ALLOW**, all heredoc-data false positives at HEAD (`cat > file <<EOF` probe scripts, `git commit -F - <<EOF` messages); every one is a correct new allow, and the 4 retained blocks are genuine sentinels (`git reset --hard HEAD~1`, `git update-ref -d …`). The one unresolved prior item is half of RT-M6: `py` is still absent from the Tier-3 interpreter regex (guard:359), so `py -c '…open(".claude/settings.json","w")…'` passes on the machine whose own hooks run `py -I`; it is not in the Known-limits bullet either. The hunt for regressions found one High: the new segment splitter treats the `&` inside redirection operators as a control operator, so `2>&1` (or `&>`) placed *before* a dangerous flag splits a single command in two and the flag lands in a phantom segment — `git push origin main 2>&1 --force`, `git reset 2>&1 --hard HEAD~1`, `git clean 2>&1 -fdx`, `git update-ref 2>&1 -d …`, `rm -rf 2>&1 <shared>` are all **HEAD-BLOCK → new-ALLOW**, a silent, unlogged evasion of the always-blocked class. Two further Mediums are the per-line quote state in the heredoc scanner (a regression false positive on a multi-line quoted commit message that quotes a `bash <<EOF` example, and a cross-line fail-open that contradicts the new "only an unquoted `<<` opens a heredoc" claim) and the bypass×cd interaction (a bypassed `cd` is skipped for cwd tracking, so the prefix disarms a later Tier-2 check, and the block banner's remediation loops for a cd-chained Tier-2 block in a shared cwd). None of the new fail-opens appears in the replay corpus; all require a specific token placement. All probes were strings passed to `check_command(cmd, cwd)` with `_shared_prefixes` monkey-patched to a tempdir (except the replay, which used real prefixes); nothing was executed.
