## Noted, not blocking

- `«…»` names bypass the ASCII rule because the name check sees the stripper's underscores (`def «Real.sqrt»`, `def «ƒ»` → no problem). Guillemets are visible, and an atomic `«A.b»` is not the hierarchical `A.b`, so no shadowing; still, checking the raw line for `«` would close it in one clause.
- Indented `alias plus := Nat.mul` and `unif_hint …` pass the statement-file rules (static layer only; Mathlib/core commands not exercised on the core fixture). Column-0 forms are rejected as unexpected commands. Adding `alias` and `unif_hint` to `STATEMENT_BANNED` costs nothing.
- A package whose `lean:` name is `Mathlib.<Name>` may import its own `Mathlib.*` modules under the Mathlib-only rule. Visible on the node and the card; would clash with a real Mathlib dependency.
- The manifest URL rule accepts any `leanprover`/`leanprover-community` repo for the `mathlib` package, not `mathlib4` specifically. Not exploitable without owning such a repo.
- `formalizer.md:35` omits the manifest and project scan from the statements-mode list (doc only).
- `meta`/`elab` as binder names, and a continuation line that starts with a binder named `prefix`, still fail the scan (honest-use false positives, by the agreed design).
- `.lake/packages/<n>/.git` absent skips the checkout HEAD check silently; reaching that state needs shell access.
