## Verdict

The documents match the validator on almost every mechanical detail, and the mainline (agree) path works end to end. Verified empirically (`py -I`, scratch script, 2026-10-14): a naively filled copy of `templates/theory/fidelity-card.md` — header fields filled, sample row replaced with `same`/`weaker` rows plus an owner `missing` row with `—`, `Verdict`/`Signed off` set per the template's own comment — returns `checklist_problem = None`, `duplicated_fields = []`, and both `blueprint_check.header_fields` and `lean_check.card_fields` read all eight header fields including `Independent audit`; the template's signature form matches `SIGNED_OFF_RE` and its override form matches `OVERRIDE_RE` (`bin/blueprint_check.py:344-346`). The checklist heading and `Part … Mark` table header match `CHECKLIST_HEAD_RE`/`checklist_rows` (`bin/blueprint_check.py:350,376-409`); the five marks match `MARKS` (`:348`); FAITHFUL-requires-all-`same` matches `_card_problem` (`:487-493`); the audit header fields and values in `card-auditor.md` match `AUDIT_KEYS` and the equality checks (`:354,513-516`); Coverage PENDING/PASS/FAIL semantics, the newest-audit rule, the repo-relative audit path under `checks/<stem>/`, and the `lean_check --hash` sweep in `/theory status` all exist as described (`bin/blueprint_check.py:429-438,494-533`; `bin/lean_check.py:859-871`); `templates/theory/blueprint-node.md:49-58` accurately restates the new `formalized`/`verified` rules including the replay of past lines. Blindness is preserved as ADR-0005 requires: the back-translator gets the statement file only, comments stripped, no glossary (SKILL.md:93); the auditor's step 1 gets statement + file + sanity parameters, its verdict withheld until the owner signs (SKILL.md:99-106); no agent writes `Verdict`, `Signed off` or `Audit override` (fidelity-card.md:22, formalizer.md:58). Both test suites pass (184 + 204). Two flow defects remain, both off the happy path: the auditor is never given the node label and Lean name its report header must reproduce byte-for-byte, and the disagreement branch dead-ends — a validly overridden card has no written route to the `formalized` line. Three Medium documentation-versus-validator gaps (same-day audit naming, override placement, one stale "section 6" reference) complete the list.

## What was verified and held

- Template → validator agreement, empirically: filled template passes `checklist_problem`, `duplicated_fields`, both header readers (all 8 fields, first 60 lines), `SIGNED_OFF_RE`, `OVERRIDE_RE`; FAITHFUL-with-non-`same`-rows is caught; the `missing`-row-with-`—` convention parses.
- `Audited statements` wording ("every `<x>` with a `<x>_stmt`") matches `parse_statement_file`'s names-without-`_stmt` (`bin/lean_check.py:267-311,692-696`).
- `python3 bin/lean_check.py <node> --hash` exists and does what SKILL.md's status sweep and the template header say (`bin/lean_check.py:859-871`).
- An unsigned card passes `lean_check --statements-only` (its card check reads Node / hashes / Lean / SHA / Audited statements only, never `Signed off`), so formalize step 2 and formalizer step 5 are correct that signing is the validator's later check (`bin/lean_check.py:676-697`).
- Formalizer reset-in-place instruction matches the `duplicated_fields` error's remediation text (`.claude/agents/formalizer.md:35`; `bin/blueprint_check.py:480-483`).
- Actor `user`, card-as-locator, statements-/full-mode report requirements, newest-full-report revocation, and the replay of past `formalized`/`verified` lines in `blueprint-node.md:49-58` all match `_check_node` (`bin/blueprint_check.py:772-825`).
- Blindness: back-translator sees the comment-stripped statement file only; auditor step 1 never sees card/back-translation/verdicts and records its verdict before seeing the checklist (step 2); owner marks and signs before the audit verdict is shown; no agent writes `Verdict`/`Signed off`/`Audit override`.
- `py -I bin/test_blueprint_check.py` → 184 passed; `py -I bin/test_lean_check.py` → 204 passed (includes `test_card_template_readable` on the new template).
