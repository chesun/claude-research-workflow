## Verdict

v2 is a genuine hardening pass: 14 of the 18 v1 findings are fully resolved, including both High symbol-table findings (the table is gone, each reader derives its own glossary, the diff is restored), the audit artifact (a report file with SHA, verdict and coverage, checked by the validator), the calibration contamination (fresh sealed set of five, answers outside the repo, one dispatch per case), and the retro audit (moved into the Decision). The v1 Critical is PARTLY resolved: the sha-prefix signature mechanically closes v1's concrete scenario (header regenerated, old signature untouched — the prefix no longer matches), but the binding is card-internal. `bin/blueprint_check.py` compares the signature, the card header and the lean_check report headers to one another and never hashes the statement file; only a lean_check *run* does (`bin/lean_check.py:689-691`). So the strongest surviving scenario — an edit to the statement file after the last lean_check run — leaves `formalized` and `verified` standing with a signature bound to a statement version that no longer exists on disk, and v2's "Rules out … a signature carried over to a changed statement" (line 89) overclaims while the known-limit paragraph (line 38) names forgery and prose edits but not this drift. v2 also introduces one defect of its own that is not merely textual: the new signature-date rule ("no later than the evidence line's date", lines 32, 85), applied by a validator that replays every historical log entry (`blueprint_check.py:510`), is already unsatisfiable for the pilot — any re-signature dated 2026-10-14 or later violates it against the pilot's `formalized` line of 2026-10-13 — so item 4's rollout cannot pass the validator change it ships with, except by backdating the signature, which falsifies the record the binding exists to protect. Fix the date rule, the drift overclaim, and the blind-author/paper-notation contradiction before Decided; the rest is text.
