# Blueprint validator Review — red-team
**Date:** 2026-10-11
**Reviewer:** red-team critic (independent, general-purpose agent)
**Target:** bin/blueprint_check.py, bin/test_blueprint_check.py
**Score:** 58/100
**Status:** Active

## Verdict

The parser and the state machine are solid: header injection, duplicate sections, CRLF/BOM, non-UTF-8 and UTF-16 files, directories named like nodes, NUL bytes and illegal characters in locators, UNC and `\\?\` paths, `..` escapes, NTFS alternate streams, case-variant and trailing-dot spellings, `./`/`../` round trips, directory junctions, rung-skipping, leaving a terminal state, and a 4 MB adversarial log line all produced FAIL or UNVERIFIED (or were deduplicated) without a crash. The gate fails where it matters most, though: every evidence rule (E1, E3, E5, downgrade) reduces to `Path.exists()`, and that is satisfied by directories (`.`, `.git`, `theory`), by any unrelated file (the node's own file, a search script, a zero-byte file), and on Windows by the reserved device name `nul` anywhere under the root, so a claim can climb to `checked` with no verifier report on disk. The validator also hashes only the statement, so the proof a verifier signed off on can be replaced wholesale while the node stays `checked`. A 1,100-node dependency chain crashes the CLI with `RecursionError` (exit 1, indistinguishable from FAIL). Fifty-three tests pass but none covers directory or device-name locators, and the plan's `g2_duplicate_label` test is absent. The score sits below the 80 commit gate because the Critical and the first High finding defeat the validator's one job, with one-line repros; the fixes are small.

All probes were built under the session scratchpad (`...\scratchpad\fx\repoN\`), each a throwaway tree with `.git/`, `theory/blueprint/checks/a/s.py`, `quality_reports/reviews/r1.md`, `r2.md`, `README.md`. In the snippets below, `bc` is the module loaded from `bin/blueprint_check.py`, `write_node`/`climb` are the test file's own helpers (copied verbatim), `R1`/`R2`/`CHECK` are the repo-relative paths just listed, and `rep = bc.check_blueprint(bp, root)`. Python 3.14.8 on Windows 11.

## Known limits (by design)

- **The actor field is free text.** `proof-verifier`, `user`, `theorist` are strings anyone can type. The validator cannot authenticate who wrote a log line; E2–E4's actor rules bind only honest agents. Authentication would need signed commits or a hook that records the dispatching agent.
- **Statement immutability is self-attested.** The hash is computed from the file itself, so an editor who rewrites the statement *and* every `stmt:` value passes (probed: `PASS`). The check catches careless edits, not deliberate ones. Detecting the latter needs history: compare against the committed version (`git show HEAD:<file>`), or pin the hash in a separate append-only ledger.
- **Append-only is not checkable from a snapshot.** Reordering, inserting or deleting log lines is detectable only insofar as the `frm`/`to` chain breaks (it does for most rewrites); a consistent rewrite is invisible without history.
- **Evidence content is not read.** A check file under `checks/`, a counterexample, or a verifier report is never opened; existence is the whole test. Finding 3 recommends the minimum content check; full assurance needs a human to read the report.
- **12-hex (48-bit) hash prefix** is collision-resistant against accident, not against a determined search; acceptable for this purpose.
- **`imported` nodes:** the spec's "stays at `conjecture` until reading notes exist" is not enforced (Phase 1 plan does not require it). URL/DOI locators are rejected as missing files, so imported evidence must be a file in the repo.
- **`formalized`/`verified`** require only the `user` actor; the `lean` field is not required until Phase 2.
- **Hidden text in the Statement** (HTML comments, zero-width or bidi characters) is hashed but may render differently from what a verifier reads; the validator cannot tell what a reader saw.
- **Only Edit/Write-mediated edits are gated elsewhere;** the validator itself is a snapshot check and runs only when invoked.
