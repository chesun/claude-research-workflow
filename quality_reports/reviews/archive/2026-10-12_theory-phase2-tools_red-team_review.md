## Verdict

The three suites pass (117 / 30 / 45 checks, Python 3.14.8, Windows 11) and the lint reports PASS on the repo's 38 live agent and skill files. The blind input is clean for the shapes the tests cover: comments are stripped, no `paper_ref`, log or verdict reaches the verifier, and `verify-input` refuses an unproved node, an unchecked claim dependency, a superseded definition and a proof that cites an undeclared node. The gaps are at the edges of each tool's contract rather than in its core. Two are High: `repoint --apply` demotes a dependent at `checked` but does nothing about nodes at `checked` that rest on it, so the dry run promises a clean move and the apply leaves a blueprint at FAIL (`prop:top is 'checked' but depends on prop:k at 'survived-search'`); and the cited-label check reads only the `## Proof`, so a `## Statement` such as "Under asm:zz-sentinel, V is concave" with `uses: []` passes the validator and produces a "ready" blind input without the assumption's statement, which is the lem:band defect the check was written for, one section up. Several Mediums follow from `verify-input` trusting the node file instead of the validator (an edited proof or statement, or a `checked` dependency on an unchecked foundation, all report "ready" and print a proof hash the log does not carry), from `_rewrite` writing files one by one with no pre-flight (a read-only or lone-CR dependent leaves the blueprint half-repointed, traceback, exit 1), and from `agent_lint` accepting an empty `description:` whenever any other key has an indented block. The score sits under the 80 commit gate because the two Highs defeat the stated purpose of the feature they belong to with one-line repros; every fix is small and local.

Every probe ran in a throwaway tree under the session scratchpad (`rt_*\repoN\` with `.git/`, `theory/blueprint/checks/<label>/s.py`, `quality_reports/reviews/`), built with the test file's own helpers (`fx.mkrepo`, `fx.write_node`, `fx.claim_at`, which also writes two valid proof-verifier PASS reports for a `checked` node). `bc` / `bt` / `al` are the modules loaded from `bin/`. Nothing in the repo was touched. PyYAML is not importable from `.venv`, so lint expectations are reasoned from YAML 1.2 (js-yaml behaviour) and labelled as such.

## What held

Tried and found sound: comments inside `## Statement` of used nodes are stripped from the input; `paper_ref`, `stmt:` hashes, `Evidence log` never appear; `verify-input` refuses an unproved node, an unchecked claim dependency, a missing dependency file, a superseded definition and an undeclared cited label; the template file (`templates/theory/blueprint-node.md`, copied as `prop-example.md`) parses with `mentions == []` despite the text "mentions:" inside its long comment; `repoint` dry run writes nothing, refuses a live node and a would-be cycle without writing, dedupes an already-present successor, skips terminal dependents, preserves CRLF and BOM on clean files, and the appended log line validates (`LOG_RE` accepts actor `blueprint-tools`, both locators exist, `down` needs no proof hash); `blueprint_tools.py` exit codes are 0/1/2 as documented on the normal paths (usage, missing file, refusal, success); `CITED_RE` ignores URLs, times, `foo:bar`, self-citations, uppercase variants and labels inside comments; `agent_lint` catches `: `, trailing `:`, ` #`, indicator starts, unclosed quotes and flow lists, tabs, duplicate keys, non-key lines, missing name/description, alias-only model, CRLF and BOM.
