## Verdict

Most of round 1 is closed and pinned: the check file now imports the signed statements before the proofs with full names (`rf_check_file_imports_statements_first`, `int_rt_proof_redefines_statements_fails`), `leanchecker <Pkg>` really does replay every olean under the package prefix (confirmed: a forged declaration in an orphan module nobody imports gives rc 1, even after its source is deleted), the project-wide scan catches `skipKernelTC`, `axiom`, `#` commands, `import Lean` and bare syntax-extension heads at any indentation and behind attributes, the `_stmt` closed form and the card's `Audited statements` list are enforced, the stripper handles char and raw literals, a missing `leanchecker` is UNVERIFIED, wrapped axiom lists parse, and the validator's hollow-report, signed-off, Node-statement-hash, UNVERIFIED-warning, `_1` and same-date rules all behave as the tests say. All four suites are green here (112 / 13 / 145 / 74), and the full formalize → sign → statements report → `formalized` → prove → full report → `verified` sequence runs end to end with a card filled from the template and reports produced by `render_report` (not hand-written ones). A realistic Mathlib statement file (`open Real`, `open scoped BigOperators`, a `structure` with fields, a `Finset.sum`, `fun`/`match`, a unicode helper name, doc comments mentioning "axiom" and "notation") and proof file (`@[simp] lemma`, `calc`, `set_option maxHeartbeats … in`, unicode binders) pass the classifier with no problems and compile clean under Mathlib's standard linter set with warnings as errors. Two things remain wrong. **Critical:** the syntax-extension ban is a head-word check, so `open Nat in macro_rules | …` (one line), `set_option maxRecDepth 100 in notation …`, `notation:50`, `infixl:65`, `macro:max`, `syntax:max` and Mathlib's `scoped[Real] notation …` all pass the scan, and the generated check file's run still reads only the exit code; a proof file of four `theorem … : True := trivial` plus one trailing `open Nat in macro_rules` line gets `LEAN CHECK: PASS (full)`, exit 0, on the real toolchain. Round-1 Critical 2 is therefore narrowed, not closed, and the regression test pins only the bare head. **High:** an indented `def <x>_stmt` or one preceded by a same-line comment is silently excluded from the audited set, contradicting `lean-layout.md` line 62. Below those: the card's `Node statement hash` is assigned to nobody and not checked by `lean_check`, so the documented sequence ends in a validator error; and a handful of false FAILs on legal spelling (`def x_stmt: Prop`, `@[expose]` on its own line, `#[…]` on a continuation line, match arms at column 0).

Repro harness: fixture copied per case to the session scratchpad (`…\scratchpad\lc\<case>`), node + card + `lean.toml` in a sibling `repo/`, run via `py -I bin/lean_check.py <node> --timeout 600` or the module API; Mathlib probes compiled read-only with `lake env lean` from `C:\Users\christina.sun\lean\bdd` on files kept in the scratchpad. Nothing in the repo, the bdd project or sibling repos was modified. Line numbers refer to the staged files.
