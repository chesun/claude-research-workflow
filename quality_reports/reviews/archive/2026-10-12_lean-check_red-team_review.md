## Verdict

The gate does not yet deliver its one promise: that a full-mode PASS means the kernel accepted a proof of exactly the signed statement. Three independent attacks, each run for real against the pinned toolchain (Lean v4.35.0-rc4, fixture copied to a short `%TEMP%` path), produce a full PASS with no proof of the audited statement at all: (1) a proof file that never imports the statement module and redefines every `*_stmt` as `True` (the generated check file imports only `Proofs`, so the attacker's definitions are the only ones in scope); (2) a `macro_rules` in the proof file that rewrites every `theorem` command, which is live inside the generated check file because macros are persistent and no syntax-extension command is forbidden; (3) a forged declaration added under `debug.skipKernelTC` in a helper module, which the token scan never reads and which `leanchecker Fix.Proofs.Thing` never replays (its `replayFromImports` trusts imports by design). Four further High findings let the statement file carry banned or unaudited declarations past the parser (indentation, same-line attributes, `_stmt` defs outside `namespace Fix`, `_stmt` defs the anchored regex does not see). What is sound: hash normalisation, card/hash binding, the proof-of-other-statement check, axiom parsing, the UNVERIFIED paths, leanchecker's catch of forgery inside the proof module itself, the validator's newest-report, first-field-wins, cross-directory and re-signed-card rules, and all three suites (66, 136, 74 checks) pass. Each Critical has a confirmed remedy (see Recommendations); none requires new design, only tightening what the plan already specified.

Repro harness: fixture copied per case to `C:\Users\<user>\AppData\Local\Temp\lcrt\<case>\proj`, node + card + `lean.toml` in a sibling `repo/`, `lean_check.check_node(node, timeout=600)` via the module API. Line numbers refer to the staged files.

## Sound (checked, no finding)

- Hash: `_normalize` makes the SHA stable under CRLF/BOM and sensitive to a helper-def edit (`lc_crlf_bom_hash_stable`, `int_helper_edited_after_signing_fails`; card-hash mismatch FAILs in both modes).
- Statement match for a proof of a *different* type when the statement module is actually imported (`int_proof_of_other_statement_fails`); name resolution prefers `Fix.x` over `_root_.x`, so root-level shadowing from the proof file does not work once #1/#6 are fixed.
- Axiom parsing: `sorryAx`, a project axiom, `decide +native`'s private axiom all FAIL; unicode names and the "does not depend on any axioms" form parse.
- leanchecker catches an unchecked declaration inside the proof module itself (`t8b`) — the backstop is real where it is pointed.
- UNVERIFIED paths: no `lake`, no/dangling project, `--no-leanchecker`, leanchecker absent, timeout — none can PASS.
- Validator: newest full report wins (`bc_newest_report_wins`); a newer statements-mode FAIL does not demote `verified`; first `**Key:**` occurrence wins (an injected later `Verdict` is ignored); a report in another node's `checks/` directory is not accepted even with a matching `Node` field; a deleted card fails the transition; re-signing the card to a new hash invalidates the old transition reports until new ones exist.
- Suites: `test_lean_check.py` 66/66, `test_blueprint_check.py` 136/136, `test_blueprint_tools.py` 74/74 on this machine.

## Unconfirmed

- An `initialize IO.println …` in an imported module could print a spoofed axiom line at import time; not run because the real `#print axioms` line comes later and overwrites it in `seen`, and because #2 subsumes it. The project-wide ban on `initialize` in #2 covers it anyway.
- Substituting the `mathlib` dependency with a fork (manifest/lakefile are outside the hash): only the revision is recorded in the report; the validator does not compare it. Not exercised; low practicality.
- `lake build --wfail` on an already-built module replays cached warnings in current Lake; if a future Lake stops replaying, a `sorry` warning from an earlier plain `lake build` would be missed by the build step (the axiom check would still catch `sorryAx`). Not tested.
- `lake env leanchecker` when the binary is absent: the fake-runner test covers rc 127/"not found"; the real Lake error text on Windows was not observed.
