## Verdict

The plumbing is right and the suites prove it: all four run green here (`test_lean_check` 66/0, `test_lean_check_integration` 10/0 against Lean v4.35.0-rc4 via the `~/.elan/bin` fallback, `test_blueprint_check` 136/0, `test_blueprint_tools` 74/0), the whole-file hash is CRLF/BOM-stable and changes when a helper `def` changes, statements mode builds only the `Statements` target and reads no proof file, reports are dated and never overwritten, the exit codes and flags match the plan, and the validator's card and report rules implement the Interfaces (signed card with matching `Node`/`Lean`/hash at `formalized`, newest full-mode PASS report with the card's hash at `verified`, a later FAIL demotes). A realistic Mathlib statement file (`@[expose] public section`, doc comments, `noncomputable def`s, a `def x_stmt :` broken over lines) parses cleanly. Two things are wrong rather than weak, both confirmed with the real toolchain on a copy of the fixture. First, the generated check file is parsed with the proof module's syntax extensions in scope, so one `notation` or `macro_rules` line in `Proofs/<Name>.lean` makes a proof of `True` pass every check (statement match, axioms, leanchecker): the plan's Review Focus 2 defence does not hold, and the token scan does not ban the commands that defeat it. Second, the forbidden-token scan reads only the statement and proof files (the plan says the project's own sources, `.lake/` excluded) and `leanchecker` is run on `<Pkg>.Proofs.<Name>` only, which re-checks that module's own constants and trusts imported `.olean`s; a `False` planted in a helper module under `debug.skipKernelTC` passes all eight checks, while `leanchecker Fix.Helper` and `leanchecker --fresh` both reject it. Below those, the statement-file whitelist is line-based and skips indented lines and anything after `@[`, so `variable`, `instance`, `theorem` and `notation` all slip in with one leading space or an attribute; `_stmt` defs that are parameterised, universe-polymorphic, non-ASCII or unannotated are silently dropped from the audited set; a wrapped `#print axioms` list gives a false FAIL; and a missing `leanchecker` under `lake env` is reported as FAIL, not UNVERIFIED. Every finding fails closed except the two Criticals, which fail open.
